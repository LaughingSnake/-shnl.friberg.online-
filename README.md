# 弗一把 · 单人模式助手

给 [shnlfriberg.online](https://shnlfriberg.online/) 的 CS Major 选手猜测游戏「弗一把」写的**单人模式求解插件**（Tampermonkey 油猴脚本）。

它会自动读取你每一行猜测的颜色 / 箭头反馈，实时算出**所有仍然可能的答案**、给出**信息量最大的下一猜**，并且**点开任意选手就能看到完整资料**。

```
┌────────────────────────────────────────────┐
│ 弗一把 · 单人助手            刷新 设置 —    │
├────────────────────────────────────────────┤
│ 可能的答案  7 人 · 当前池 646 人          复制 │   ← 面板调矮时第一眼看到的就是它
│  NiKo（波黑）  Falcons · 波黑 · 28岁 · 步枪手│
│  完全一致                                   │
│  ──────────────────────────────────────  │
│  已读取 1 行猜测。目标在所选难度池中随机产生… │   ← 说明文字排在名单下面
├────────────────────────────────────────────┤
│ 推荐下一猜                            重算  │
│  1. m0nesy   猜后平均剩 3.10 人 · 最坏 9 人 │
│  2. ropz     猜后平均剩 3.42 人 · 最坏 9 人 │
```

## 一、安装

1. 浏览器装 **Tampermonkey**（油猴）扩展。
2. 打开 [`dist/friberg-single-helper.user.js`](dist/friberg-single-helper.user.js)，Tampermonkey 会弹出安装页；或把文件拖进浏览器、或复制内容到 Tampermonkey「添加新脚本」。
3. 打开 <https://shnlfriberg.online/> 进入**单人模式**，右下角会出现一个圆形的「弗」按钮，点开就是求解面板。

## 二、怎么用

1. **正常玩**。每次提交猜测后，插件会自动同步棋盘（无需任何操作）。
2. 「**可能的答案**」列出与你的全部反馈完全一致的选手，从上往下猜基本能锁定。
3. 「**推荐下一猜**」给出信息量最大的猜测，按 `猜后平均剩余` **从小到大**排序（越小越好：它是按每种可能反馈继续缩小范围后的平均候选数）。默认每局自动计算，也可以点「重算」。
4. 点任意选手昵称 → 弹出资料卡。
5. **窗口可以拖动和缩放**，默认 420px 宽、78vh 高会挡住棋盘，建议拉小一点：
   - 拖**标题栏**移动位置；
   - 拖**右下角的 ◢ 把手**改变大小（双击把手 = 还原默认）；
   - 位置和大小都会记住，设置弹窗里也有「还原窗口位置与大小」。
6. 如果颜色条读错了（比如游戏改版），在「**反馈修正**」里点色块手动改：`准确 → 接近 → 错误 → 未填` 循环；数字项右边的小箭头按钮切换 `↑ / ↓`。也可以「添加」一行手动补录。

### 选手资料卡

点开任一选手（候选列表、推荐列表、反馈修正列表里的名字都能点），可以看到：

| 字段 | 说明 |
| --- | --- |
| 昵称 / 当前队伍 | 与游戏内「昵称」「队伍」列对应 |
| 国家或地区 / 赛区 | 对应「国家或地区」列，赛区用于判断黄色「接近」 |
| 年龄 | 对应「年龄」列（±3 岁内为接近） |
| 位置 | 步枪手 / 狙击手 / 教练，对应「位置」列 |
| Major 冠军 / Major 参赛 | 对应「Major 冠军」「Major 次数」列（±1 内为接近） |
| 现役状态 | 对应「状态」列 |
| 所属难度 | 该选手属于 入门 / 简单 / 全部 哪些池 |
| 历史队伍 | 用于判定队伍黄色「接近」，来自 Liquipedia |

如果这一局你已经猜过他，资料卡里还会显示你当时拿到的 7 项反馈。

## 三、求解原理（完全复刻官网规则）

比对逻辑逐行对照官网服务端 `server/src/services/gameService.ts` 的 `compareGuess()` 实现：

| 字段 | 绿色（准确） | 黄色（接近） | 灰色（错误） |
| --- | --- | --- | --- |
| 队伍 | 当前队伍相同 | 猜测的队伍在**答案的历史队伍**里 | 其他 |
| 国家或地区 | 国家相同 | 国家不同但**赛区相同** | 其他 |
| 年龄 | 相同 | 相差 ≤ 3 岁 | 其他，并给出 ↑/↓ |
| 位置 | 相同 | — | 其他 |
| Major 冠军 | 相同 | 相差 ≤ 1 | 其他，并给出 ↑/↓ |
| Major 次数 | 相同 | 相差 ≤ 1 | 其他，并给出 ↑/↓ |
| 状态 | 相同 | — | 其他 |

求解 = 用你的每一行反馈去筛选手库：只有**模拟反馈与实际反馈一致**的选手才会留下。目标是从当前难度池随机抽取的，所以留下的选手概率相同。

「推荐下一猜」遍历整个难度池，把候选集按每个候选猜测会触发的反馈组合分桶，取 `Σ(桶大小²)/候选数` 最小者，即猜完之后平均剩下最少的那个。

## 四、历史队伍数据（最麻烦的一块）

队伍黄灯的判定需要**答案的历史队伍**，而官网公开接口 `/api/players` 只返回 8 个属性，**不返回 `team_history`**（只有需要 API Token 的 `/api/players/export` 才有）。所以插件自己把这份数据补齐了。

### 为什么用 Liquipedia 而不是 HLTV

按要求先试了 hltv.org：它对所有请求（首页、搜索页、选手页都试了）统一返回 **Cloudflare 的 JS 挑战页（HTTP 403，标题 "Just a moment..."）**，纯 HTTP 抓取拿不到任何数据，需要真实浏览器执行 JS 才能过盾。

于是改用 **Liquipedia**（`liquipedia.net/counterstrike`）的公开 MediaWiki API——它有结构化的 `|team_history=` 字段：

```
|team_history=
{{TH|2016-01-02 — 2016-04-21|Team Liquid}}
{{TH|2016-08-04 — 2023-10-26|Natus Vincere}}
{{TH|2025-05-05 — 2025-07-09|FaZe Clan|Loan}}
```

而且官网自己的队伍命名本身就是 Liquipedia 风格（连 `Butterfly (Russian team)` 这种消歧后缀都一样），两边对得上。

### 抓取与消歧（`tools/fetch-team-history.mjs`）

- **批量直查**：一次请求最多 50 个标题，642 个唯一昵称只需 13 个请求；
- **搜索兜底**：查不到的用 `generator=search` 一次拿到结果和正文；
- **只映射到会被猜到的队伍**：只有选手池里出现过的 114 个「当前队伍」才可能被猜出来，其余历史队伍一律丢弃——映射目标小、准确率高；
- **重名消歧**：池子里有 `NiKo（波黑）`/`niko(丹麦)`、`adren（美国）`/`adren（哈萨克斯坦）`、`steel`×2、`Lucky`×2、`ALEX`/`alex`、`Zero`×2。先按**昵称原样**查（不折叠大小写），再逐条比对 infobox 的 `|id=` 和 `|country=`，**以国家匹配优先**；
- **身份校验**：只有「country 命中」或「页面没有 country 字段但 `|id=` 命中」才采信，其余当作历史未知——宁可不用，也不张冠李戴；
- **不把解析失败当空历史**：页面里一条 `{{TH}}` 都没有时视为「未知」，而不是「没有历史队伍」。

结果：**641 / 646 名选手**拿到了可信的历史队伍（另外 5 人身份校验不通过，按未知处理）。校验方式是「选手的当前队伍几乎一定出现在自己的历史里」——命中率 **92.9%**，未命中的 23 人基本都是官网数据比 Liquipedia 新（刚加入 BetBoom / 1win / 9z 的选手）。

### 关键：只做「安全剪枝」，绝不误杀真答案

抓来的历史 H′ 基本是真实历史 H 的**子集**（Liquipedia 可能滞后，漏掉最近加入的队伍很常见；凭空多出一条几乎不可能）。所以队伍字段的约束是这样处理的：

| 反馈 | 猜测队伍 ∈ H′ | 处理 |
| --- | --- | --- |
| 灰色 | 是 | **排除**（G ∈ H′ ⊆ H，不可能显示灰色） |
| 灰色 | 否 | 保留，标记「队伍历史待确认」 |
| 黄色 | 是 | 保留，且完全可信 |
| 黄色 | 否 | 保留，标记「队伍历史待确认」 |
| 任意 | 历史未知 | 保留，标记待确认 |

也就是说：历史数据不全时只会「少剪枝」，永远不会把正确答案踢掉。测试里用「真实历史比抓取数据多 3 条」的 300 局随机对局验证过，**真答案 300/300 全部保留**。

### 自我纠错：从实战反馈里学习

猜中一局后，插件会把这一局的反馈反哺回数据（存在 `localStorage`，优先于抓取数据）：

- 某次猜测显示**黄色** → 该队确实在答案的历史里 → 记入 `add`；
- 某次猜测显示**灰色** → 该队确实不在答案的历史里 → 记入 `remove`（这一步能纠正抓取数据里多出来的脏条目）。

设置弹窗里能看到「N 人由实战反馈校正过」，也可以一键清空。玩得越多，数据越准。

> 历史队伍数据来源：Liquipedia（CC-BY-SA 3.0）。仅供个人辅助使用。

## 五、刷新选手数据

内置快照是 **646 名选手 + 641 人的历史队伍**（抓取时间见「设置」弹窗底部），离线可用、游玩时不产生任何请求。

- **有官网 API Token**：调用 `/api/players/export` 得到 `players.json`，在「设置 → 导入 players.json」里选文件即可（含官方 `team_history`，最权威）；
- **重新抓取**：`node tools/fetch-team-history.mjs` 然后 `node tools/build-dataset.mjs`；
- 选手池本身的抓取办法见 `.research/harvest.mjs`：官网 `/api/players` 每次只返回 100 条且限流 `10 次/60 秒`，用「子串贪心覆盖」挑选查询词，53 次请求就能把 646 人的完整属性抓齐。

## 六、开发

```bash
pnpm install

node .research/harvest.mjs                # 抓取完整选手池（53 次请求）
node tools/fetch-team-history.mjs         # 抓取 Liquipedia 历史队伍
node tools/validate-history.mjs           # 历史队伍数据质量校验
node tools/build-dataset.mjs .research/pool-raw.json data/players.json .research/team-history.json
node tools/build.mjs                      # 构建 dist/*.user.js

node tools/test-solver.mjs   # 规则对照 + 可靠性（300 局）+ 剪枝规则 + 性能
node tools/test-dom.mjs      # jsdom 端到端：解析 / 求解 / 交互 / 资料卡 / 学习
```

目录结构：

```
src/core.js        纯逻辑：数据集解码、compareGuess 复刻、安全剪枝、推荐算法（Node 里可直接 require）
src/ui.js          界面：悬浮面板、棋盘解析、手动修正、选手资料卡、实战学习
src/meta.js        UserScript 元数据
data/players.json  646 名选手 + 历史队伍快照（紧凑数组 + 队伍下标表，34 KiB）
dist/friberg-single-helper.user.js  构建产物（唯一需要安装的文件）
tools/             构建、抓取、校验、测试脚本
```

### 测试覆盖

- **规则对照**：队伍 / 国家赛区 / 年龄 / Major / 位置 / 状态的每种颜色与箭头逐一断言；
- **安全剪枝**：8 条断言覆盖上表所有分支（含「灰 + 队伍相同 → 排除」这类矛盾情形）；
- **可靠性**：300 局随机对局，真实历史比抓取数据多 3 条（模拟滞后），验证真答案**从未**被排除；平均候选数 `27.6 → 8.0 → 4.3 → 2.5 → 1.9 → 1.7 → 1.6 → 1.4`；
- **性能**：筛选 646 人 × 8 行约 `0.03 ms`；最坏情况（646 候选 × 646 猜测）推荐计算约 `90 ms`；
- **端到端**：jsdom 复刻官网 `table.game-table` 与 lucide 箭头 SVG，覆盖挂载、解析、候选、手动修正、资料卡、**拖动与缩放（含双击还原、尺寸持久化不会写成 0）**、设置弹窗、难度池跟随 URL（`/single/*`、`/daily/*`）、未知昵称、空棋盘，以及**猜中后的实战学习**，要求全程零页面报错。

当前两套测试共 **128 项断言（求解器 37 + 端到端 91），全部通过**。

## 七、注意事项

- 插件只读页面上的猜测棋盘，**不会**替你提交猜测、不会调用任何写接口。
- 只在 `shnlfriberg.online` 生效；数据存在浏览器 `localStorage`（`friberg-helper:*`）。
- 图标识别依赖 lucide 的 `lucide-arrow-up / lucide-arrow-down` 类名，同时保留按 SVG 路径识别的兜底；若官网大改版导致识别失败，可在「反馈修正」里手动录入。
- 选手属性来自官网公开接口，历史队伍来自 Liquipedia（CC-BY-SA 3.0），规则与数据版权归各自所有者。
